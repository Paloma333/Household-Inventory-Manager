## 视觉与交互规格扩展

> 本版本基于 v1.0 骨架（功能范围、信息架构、AI Schema、埋点等保持不变），重点补充：

> - 设计系统基础（色彩、字体、间距、组件、动效、文案）
> - 每个页面的完整交互规格（默认 / 空 / 加载 / 错误 / 成功）
> - 微交互细节、长按/滑动手势、可访问性

## 0. 写在前面：这次的"审美方向"声明

> 这一节是给 K3、做前端实现、以及将来换设计师时的锚点。先把"我们不做的事"说清楚，避免被通用 AI 审美带跑。

### 0.1 我们要什么气质
- **生活感而非应用感**：像走进自己刚收拾过的小厨房，而不是打开一个 SaaS 控制台。
- **看护感而非管理感**：我们是在帮用户照顾他们的小家，所以动作要轻、鼓励要多。
- **轻手绘而非装饰插画**：图标和点缀物用手绘笔触感，避免精致商业插画那种"塑料感"。
- **质感而非炫技**：用肌理（纸、木、棉线）说话，少用大面积渐变 / 玻璃拟态 / 阴影层叠。

### 0.2 我们不做什么（AI Slop 反例清单）
- **不要** Hero 区塞一只大眼睛卡通宠物 + 三段价值点 —— 那是 toC 营销页范式，不该出现在管理工具首页。
- **不要**渐变彩色卡片墙 —— 商品分类不该像营销活动区。
- **不要** 全圆角 + 大阴影 —— 卡片之间要有节奏，有些方、有些圆、有些是纸片贴上去的感觉。
- **不要** 拟物化沙发 / 冰箱 / 厨房 3D —— 我们的产品是数据工具,不是模拟人生。
- **不要**"宝宝 / 主子 / 萌萌哒"口吻 —— 我们说人话,偶尔有点温度,但不卖萌。
- **不要** 把空状态做成"插画 + 一句话 slogan"模板 —— 空状态需要的是**操作建议**,不是情绪安慰。
- **不要** 满屏 toast / 弹窗庆祝 —— 反馈要轻,300ms 后自己消失,该有的页面状态自然更新就行。

### 0.3 一个永远先问的问题
> "这是为了让用户**继续做完手头的事**,还是为了**展示给别人的截图好看**?"

如果答案是后者,这条交互重做。

## 1. 设计系统基础

> 本节是所有页面 / 组件的源头。K3 视觉升级时,改 token 不能改语义。

### 1.1 色彩系统

#### 1.1.1 基础色板（语义优先，非品牌色堆叠）

| Token | 用途 | Light 值 | Dark 值 | 备注 |
|-------|------|---------|---------|------|
| `--bg-canvas` | 页面最底层背景（米白/纸色） | `#F6F1E7` | `#1B1A17` | 不要纯白；颗粒感肌理 |
| `--bg-surface` | 卡片背景（浅木色） | `#FFFCF4` | `#26231D` | 卡片默认停在 canvas 上 |
| `--bg-elevated` | 浮层/弹窗背景 | `#FFFEF8` | `#2E2A22` | 与 surface 区分要靠色彩 + 1px 边线，不要靠阴影 |
| `--bg-overlay` | 模态遮罩 | `rgba(43,40,33,0.45)` | `rgba(0,0,0,0.6)` | 不要纯黑 |
| `--border-hairline` | 1px 边线 | `#E8DFCB` | `#3D372C` | 大部分场景不要 border,用纸片边代替 |
| `--ink-primary` | 主要文字 | `#2A2620` | `#F2EAD9` | 不要 `#000` |
| `--ink-secondary` | 次要文字 | `#6E6655` | `#A89F8A` | 时间戳、辅助信息 |
| `--ink-tertiary` | 占位 / 禁用 | `#A89F8A` | `#6E6655` | |
| `--accent-sage` | 主操作色（鼠尾草绿） | `#7A9471` | `#A5C39B` | CTA、active 状态 |
| `--accent-sage-soft` | 强调背景 | `#E4ECDD` | `#3E4D3A` | 选中态、低库存标签 |
| `--accent-clay` | 警示色（陶土橙） | `#C97B5A` | `#E29B7A` | 已用完、过期 |
| `--accent-clay-soft` | 警示背景 | `#F4DBC9` | `#5A3C2C` | |
| `--accent-honey` | 数值高亮（蜂蜜色） | `#D5A24E` | `#E5BC75` | 数量徽标、低置信度提示 |
| `--confidence-low` | AI 低置信度 | `#D5A24E` | `#E5BC75` | 用在确认页边框 |
| `--confidence-mid` | AI 中置信度 | `#A0AEB8` | `#8A98A2` | |

**色彩原则**：
- 暖中性（米白 / 奶白）+ 单一品牌倾向色（鼠尾草绿），不要再多。
- 警示用陶土橙，不要用红；红色显得"医疗警报"，与产品气质冲突。
- 阴影几乎不用；分层靠色彩 + 边框 + 肌理。
- 任何色卡都先经过 **WCAG AA 对比度** 校验：正文 ≥ 4.5:1，大字 ≥ 3:1。

#### 1.1.2 商品分类专属色（克制使用，仅在分类 chip 上）

| 分类 | 主色 | 背景色 |
|------|------|--------|
| 食品饮料 | `#A4B97C` | `#EDF1DD` |
| 家居清洁 | `#7B98B5` | `#E1E9F0` |
| 个人护理 | `#D7A8B7` | `#F4E3E7` |
| 健康药品 | `#B49FCB` | `#ECE3F4` |
| 衣物 | `#D4B07E` | `#F1E5D0` |
| 家用电器 | `#9AA8A1` | `#E3E8E4` |
| 其他 | `#A89F8A` | `#ECE7DB` |

> 同一个分类色不要贯穿到卡片背景/详情页大色块；只用在分类 chip 与列表点缀。

### 1.2 字体系统

#### 1.2.1 字体选择

- **中文主字体**：思源黑体 / HarmonyOS Sans / 系统默认 sans（在小程序里用 `system-ui, -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`）。
- **中文展示字体**（欢迎语、卡片标题）：首选 `LXGW WenKai`（霞鹜文楷），无则退化到思源宋体，最后到系统 serif。
- **数字字体**（库存数量）：`Inter` 或 `SF Pro Display`；数字场景禁用 Chinese numerals 字体。

#### 1.2.2 字号阶梯（流体）

```css
--font-display:    clamp(28px, 6vw, 36px);   /* 首页欢迎语 */
--font-h1:         24px;                     /* 页面标题 */
--font-h2:         20px;                     /* 区块标题 */
--font-h3:         17px;                     /* 卡片标题 */
--font-body:       15px;                     /* 正文 */
--font-small:      13px;                     /* 辅助文字 */
--font-micro:      11px;                     /* 时间戳/单位 */
```

**字重**：
- 标题用 600，避免 700（在小字号中文上会糊在一起）。
- 正文永远 400 / 500。
- 数字（库存数量）用 600 + tabular-nums。

**行高**：
- 中文正文 1.7（中文需要更松的呼吸）。
- 标题 1.3。
- 列表 1.55。

### 1.3 间距 & 圆角 & 边线

```css
--space-1: 4px;
--space-2: 8px;
--space-3: 12px;
--space-4: 16px;
--space-5: 20px;
--space-6: 24px;
--space-8: 32px;
--space-10: 40px;
--space-12: 48px;
--space-16: 64px;

/* 圆角——不要统一 */
--radius-xs: 6px;     /* chip / tag */
--radius-sm: 10px;    /* 输入框 / 小按钮 */
--radius-md: 14px;    /* 普通卡片 */
--radius-lg: 20px;    /* 大卡片 / 浮层 */
--radius-pill: 999px; /* 圆形 CTA / 头像 */

--border-paper: 1px solid var(--border-hairline);
```

**节奏**：相邻元素间距 4 / 8 互换；不要全用 16px 显得呆。
**卡片不用阴影，改用 1px 边线 + 背景差。**

### 1.4 动效原则

#### 1.4.1 通用 token

```css
--ease-out-quart:  cubic-bezier(0.25, 1, 0.5, 1);
--ease-out-expo:   cubic-bezier(0.16, 1, 0.3, 1);
--ease-in-out-cubic: cubic-bezier(0.65, 0, 0.35, 1);

--dur-tap:   120ms;   /* 按下反馈 */
--dur-enter: 240ms;   /* 元素入场 */
--dur-leave: 160ms;   /* 元素离场 */
--dur-page:  320ms;   /* 页面级转场 */
```

#### 1.4.2 规则

- **状态变化必有动效**：按下按钮缩 0.97；卡片选中加 1px 强调边。
- **避免回弹/弹性缓动**：治愈系不要"果冻感"。
- **不用 1s 以上的入场动画**：超过 300ms 的"等待型"动画一律不要。
- **页面级转场**：右滑入 + 内容上浮 12px，260ms `ease-out-expo`。
- **数字滚动**：库存数量从 X 变到 Y 时,数字 350ms 滚动到位（用 `requestAnimationFrame`），便于用户感知"少了 / 多了"。
- **微庆祝**：完成 AI 入库时，物品图标做一次 1.05 缩放 + 短暂光晕（120ms），不要整屏礼花。

#### 1.4.3 动效禁用清单

- ❌ 整屏 loading 旋转 loader，用骨架屏代替。
- ❌ 通用 toast「操作成功」横幅，依靠页面状态自然更新。
- ❌ 强制 Lottie/动画角色，说故事用文案 + 图标。
- ❌ 滚动驱动的视差/parallax，会让列表卡顿。
- ❌ 弹性 ease（back / bounce），与气质冲突。

### 1.5 文案语气

#### 1.5.1 人格
- 第一人称"我"对用户自称，避免"本应用/本系统"。
- 对用户称呼用"你"，不用"用户 / 您"。
- 鼓励而非命令：「要不要添点东西？」而不是「请添加新项目」。
- 数字单位保留口语：剩 1 包 / 2 提 / 3 卷，而不仅是 1 / 2 / 3。

#### 1.5.2 模板库

| 场景 | 反例 | 正例 |
|------|------|------|
| 首次进入 | 欢迎使用智能库存管理！ | 你的小家还空着，先带第一样东西回来吧 |
| 空状态 | 暂无数据 | 这里还没有东西，要不要拍张小票或加一件？ |
| AI 完成 | 识别成功！已添加 X 项 | 我从这张小票上找到了 X 样东西，确认一下就放进小家 |
| AI 部分识别 | 识别失败 | 这张我没看清，X 样我认出来了，剩下的手动补一下吧 |
| 低库存 | 您有 N 项库存不足 | 这 X 样快用完了，要不要列个购物清单？ |
| 已用完 | 库存为零 | 没了，下次补回来的时候告诉我一声 |
| 重复购买 | 系统检测到您再次购买 | 咦？你又买了这个 |
| 表单错误 | 请输入正确的信息 | 这格我看不出来是啥，帮我补一下 |
| 退出确认 | 确定要退出吗？ | 这次添加还没存好，要继续填还是要先存一下？ |

## 2. 组件库

> 所有页面共用一套组件库。K3 可在此基础上调整视觉，但**组件命名和 prop 不要变**。

### 2.1 按钮

```
Btn
├─ variant: primary | secondary | ghost | danger | subtle
├─ size:    sm (32px) | md (40px) | lg (48px) | xl (56px 主 CTA)
├─ state:   default | pressed | disabled | loading
└─ iconLeading | iconTrailing | iconOnly
```

- `primary`：鼠尾草绿填充 + 米白文字；按下缩 0.97 + 颜色加深 8%。
- `secondary`：纸色填充 + 1px 边线 + 深棕文字。
- `ghost`：无背景，仅文字；仅在次要操作使用。
- `subtle`：hover 才显形的"幽灵按钮"，用于列表项展开。
- `danger`：陶土橙填充，仅用于"删除"类破坏性操作，且需二次确认。
- **`iconOnly`** 直径 ≥ 44px（触屏可达性）。

**禁用态**：opacity 0.45，不要用灰色禁用样式（破坏色彩温度）。

### 2.2 卡片

```
Card
├─ kind:   product | category | lowStock | change | empty
├─ state:  default | pressed | selected | swiping
└─ slot:   thumb | title | meta | trailing
```

- 商品卡：左 thumb（48x48 浅米色底 + 商品首字） + 名称 / 单位 / 当前数量徽标。
- 长按卡片：底部浮出操作条（数量 +/-、编辑、删除），不弹菜单。
- **左滑卡片**：删除（带 undo toast 5s）；不要右滑，避免与微信"返回"手势冲突。

### 2.3 输入

```
Input
├─ kind:    text | number | stepper | date | chips
├─ state:   default | focused | filled | error | ai-suggested
└─ slot:    label | helperText | trailingIcon
```

- 数字输入用 stepper（数量 +-），不弹键盘。
- `ai-suggested` 状态：字段边框为蜂蜜色 + 旁边小角标"AI"，用户点击可一键确认。
- 错误态文字在下方 8px 处，红字陶土橙色；不要抖动/摇晃动效。

### 2.4 列表项

- 列表默认 56px 高，分类 chip 32px。
- 列表分割线用 `--border-hairline`，且只在空白处的列表项间显示（inset divider）。
- 长列表第一屏超过 12 项时启用骨架屏。

### 2.5 空状态

```
EmptyState
├─ illustration: mutedLine (线稿)/ paperTear (撕纸)
├─ title:        1 句话说明原因
├─ action:       1 个主操作
└─ secondary:    可选 1 个次要操作
```

- 永远带 1 个 CTA；不要纯展示型空状态。
- 插画用线稿（≤ 80x80px），不用大色块插画。

### 2.6 加载 & 反馈

- **页面级**用骨架屏（4 行 + 2 个卡片形状），不用 spinner。
- **行内**用小色块闪烁动画（200ms）。
- **Toast** 仅用于撤销提示（5s）和错误信息（手动关闭）；成功不弹 toast。
- **AI 处理中**用拟态文案：
  - "我正在看这张小票..."
  - "几乎好了..."
  - "差一点点..."
  三句轮换，每 1.2s 切换，不要 spinner。

### 2.7 模态 / 弹窗

```
Modal
├─ type:      dialog | sheet | popup | fullscreen
└─ behavior:  esc | swipeDown | backdropClick
```

- 重要确认（删除、永久操作）用 dialog，宽度 280px。
- 重复购买确认用 sheet（从底部弹出，圆角顶部 20px）。
- 拍照选择等从底部弹的选项表用 action sheet。
- 弹窗背景遮罩：`bg-overlay`，不要纯黑。

### 2.8 标签 / Chip

- 分类标签：圆角矩形 + 浅分类色 + 深分类文字；永远不与卡片其他操作重复。
- 低库存标签：陶土橙文字 + 浅橙底，不带图标。
- AI 置信度：低置信度用蜂蜜色描边 + "建议确认"文字；中置信度用灰色描边 + "可保留"。

### 2.9 进度 & 数字滚动

- 库存数量变更：350ms 数字滚动（从 previous → new）。
- 首页统计卡片：进入时数字从 0 滚动到位，400ms。

### 2.10 手绘风图标集

> K3 设计时请保持图标线宽 1.5px，圆角端点。

- 必备图标：购物袋、相机、截图、铅笔、放大镜、勾选、叉、爱心（收藏）、钟（历史）、垃圾桶、分享、设置、用户、分类饼图。
- 图标用 2 种风格：
  - **实心**：`accent-sage` 填充，用于主 CTA 旁边的图标。
  - **线稿**：`ink-secondary` 1.5px，用于导航、列表前缀。
- **禁止** emoji 代替图标——emoji 会因系统/平台不同而风格分裂。

## 3. 页面交互规格

> 每个页面输出五件套：① 目标与用户心理 ② 信息层级 ③ 组件清单 ④ 状态规范 ⑤ 关键交互与微动效

### 3.1 首页 / 我的小家

> 对应原 PRD 7.1

#### 3.1.1 目标与用户心理
- **目标**：让用户在 2 秒内看到"今天需要关心什么"，并在 5 秒内完成"添点东西"。
- **心理**：打开 app ≠ 想做任务，是想"瞥一眼家里状况"。我们要给"瞥见"提供条件，而不是塞满信息。

#### 3.1.2 信息层级（自上而下）

```
┌─────────────────────────────────────────┐
│  早上好，阿橙的小家  [天气/日期小字]      │  ← 欢迎区 96px
│  家里有 84 件东西，分 7 类                │  ← 数字一句话
├─────────────────────────────────────────┤
│  [纸片卡片：低库存 5 件]→                │  ← 横向滑动卡 124px
│  [纸片卡片：最近变化 12 件]→              │
├─────────────────────────────────────────┤
│  分类                                    │
│  🍞食品饮料(32)  🧴家居清洁(14)  ...    │  ← 分类 chip 流
│  💊健康药品(2)   👕衣物(8)  ...         │
├─────────────────────────────────────────┤
│  最近变化                  [查看全部 →]   │
│  • 抽纸 −1      今天 14:23              │  ← 列表（前 5 条）
│  • 新增：酸奶   昨天 22:10              │
│  ...                                     │
├─────────────────────────────────────────┤
│                  [+ 添点东西]            │  ← 主 CTA 居中悬浮 56px
└─────────────────────────────────────────┘
```

#### 3.1.3 组件清单
- `WelcomeBanner`（欢迎语 + 小家名）
- `StatLine`（数字一句话：`家里有 {N} 件东西，分 {M} 类`）
- `CardCarousel`（左右滑动卡片：低库存 / 最近变化 / 待补货）
- `CategoryChipFlow`（最多展示前 6 类 + "其他"折叠）
- `RecentChangeList`（最多 5 条，"查看全部"跳到库存页全部时间筛选）
- `FloatingActionButton`（+ 添点东西，主操作）

#### 3.1.4 状态规范

| 状态 | 触发条件 | 展现 |
|------|---------|------|
| 默认 | 有库存 | 上述布局 |
| 空状态 | 无任何 item | 欢迎语改为「你的小家还是空的」，CTA 改为「带第一样东西回来 →」；分类区消失 |
| 加载 | 首次进入 500ms 内 | 欢迎语直接显示骨架，其余卡片骨架 |
| 错误（接口 5xx） | 网络故障 | 顶部出现 1 行黄色提示条「家里和我的小家暂时连不上，刷新试试」 |
| 刚添加完返回 | 携带 `just_added=1` 参数 | CTA 上方显示一个"刚刚放进了 X"的卡片 3 秒后消失 |

#### 3.1.5 关键交互

- 文案有温度，让"再买"不显得是重复劳动。

#### 3.6.2 形态

- **底部 sheet**（非全屏），高度自适应，圆角顶部 20px。
- 背景遮罩 `bg-overlay`。

#### 3.6.3 信息层级

```
┌─────────────────────────────────────────┐
│              ───                        │  ← 拖把
│  🤔 咦？你又买了这个                      │
│                                          │
│  ┌─────────────────────────────────┐    │
│  │  清风原木纯品抽纸                  │    │
│  │  上次：1 提        这次：1 提      │    │
│  └─────────────────────────────────┘    │
│                                          │
│  家里现在还有多少？                        │
│  （先告诉我，我帮你算新的库存）              │
│                                          │
│  [已用完啦  🙂]    [还剩点  ✏]            │  ← 两个并列按钮
│                                          │
│  [永远把它当成不同商品  ▾]                 │  ← 次要折叠
│                                          │
│                       [取消]              │
└─────────────────────────────────────────┘
```

#### 3.6.4 关键交互

- **点 [已用完]**：
  - 上次库存数字闪一下变成 0（200ms）。
  - 新库存只算"这次买"的数量，显示在屏幕底部 0.5s 提示"新的库存：1 提（6 包）"。
  - 自动确认 → 关闭 sheet → 在原页面继续。
- **点 [还剩点]**：
  - 展开输入框：`还剩 [____] [提 / 包]`，可滑动或 stepper。
  - 同时下方实时计算：`最终库存 = {剩 N} + {新买 M} = {总}`，带轻数字滚动。
  - 确认后关闭。
- **永远当成不同商品**：
  - 展开后展示"这俩不是同一种"的简短理由（自由文本 + 跳过）。
  - 用户可填入"商品名 / 数量"创建新商品；不强制。
- **取消**：什么都不做，旧库存保留原状，新购买被暂存为草稿（首页有提示）。

#### 3.6.5 状态

| 状态 | 展现 |
|------|------|
| 默认 | 上述布局 |
| AI 无法判定是否同款 | 显示候选：可能是『XX』也可能是『YY』，请你看看 |
| 旧库存为 0 | 不弹此 sheet，直接入库（无歧义） |
| 用户首次遇到 | 顶部灰色 helper "以后再买相同东西，问我一下旧的是不是用完" |

#### 3.6.6 微动效
- sheet 进入：从底部上推 280ms `ease-out-expo`，背景遮罩 200ms 淡入。
- 已用完分支：旧数字 1 → 0，350ms 滚动 + 数字短暂变陶土橙再回到中性。
- 还剩点分支：输入区展开 200ms `ease-out-quart`，下方总库存数字滚动到位 220ms。

#### 3.6.7 文案
- 主："咦？你又买了这个"
- 副："家里现在还有多少？"
- 已用完："已用完啦 🙂"
- 还剩："还剩点 ✏"
- 永远不同："以后再出现就当我买了不同的"
- 取消："取消"

## 4. 微交互 & 手势规范

### 4.1 全局手势
- **左滑卡片删除**：列表项通用动作；不要反着右滑（与微信"返回"手势冲突）。
- **下拉刷新**：所有页面顶部下拉；刷新成功的反馈必须可感知（数字滚动、文字变更）。
- **长按 0.4s** 显示上下文菜单 / 操作条。
- **双击主 CTA**：禁用，避免误触。
- **边缘右滑返回**：使用系统默认行为。

### 4.2 转场
- **页面 push**：右侧滑入 + 内容上浮 12px，260ms `ease-out-expo`。
- **页面 pop**：反向，左侧滑出 + 内容下沉。
- **底部 sheet**：从底部上推 280ms `ease-out-expo`。
- **dialog**：背景遮罩 200ms 淡入 + 居中缩放 0.94→1.0（220ms `ease-out-expo`）。

### 4.3 按下反馈
- 所有按钮 / 卡片：**按下** 状态必须明显：缩 0.97 + 背景加深 4%。
- 持续按下 0.5s 后开始长按菜单。

### 4.4 数字变化
- 库存数字 / 欢迎语统计数字：**滚动到位**，350ms 内完成。
- 滚动方式：用 `requestAnimationFrame` 或 `setTimeout(linear)`，不要用 CSS transition（在 iOS Safari 偶发掉帧）。

### 4.5 反馈
- **成功**：页面状态自然更新，不弹 toast。
- **失败**：行内错误文字（不摇晃 / 不闪烁），错误持续到用户操作。
- **撤销**：删除类操作后底部出现 undo bar 5s，可恢复。
- **AI 进行中**：3 句轮换文案，不用 spinner。
- **网络异常**：顶部黄条，可关闭。

| 概念 | 触发 | 形式 | 时长 |
|------|------|------|------|

## 6. 跨页面动效叙事节奏

> 用户从打开 app 到完成首次添加，应该有 1 个完整的"曲线"。

1. **进入首页**：欢迎语从 12px 上浮到位；数字 0 → 滚动到位（400ms）。→ **感受：被问候**
2. **+ 添点东西**：FAB 按下缩 → ActionSheet 弹出。→ **感受：被引导**
3. **拍 / 选图**：调用原生相机/相册。→ **感受：顺畅**
4. **AI 处理**：3 句轮换文案，骨架屏。→ **感受：被陪伴**
5. **AI 完成**：卡片 stagger 入场。→ **感受：被确认**
6. **用户确认**：主 CTA 进入 loading → 卡片离场 → 成功过渡页（3.1s 内）。→ **感受：被祝贺**
7. **返回首页**：首页上方出现"刚刚放进 X"卡片 3s → FAB 上滑 4px 收尾。→ **感受：被记住**

不要在第 4 步前后插入额外弹窗 / 教程 / 推送权限请求等打断节奏。

## 7. 可访问性 / 无障碍

> 微信小程序对 a11y 支持有限，但 Web 端必须做。

- 所有按钮有 `aria-label`（中文下要写清楚）。
- 颜色不是唯一信息载体：低库存必须有文字标签，不能只靠橙色。
- 文字大小遵循用户系统设置（小程序使用 `rpx` 自适应；Web 端 `1rem = 16px` 起步）。
- 触屏目标 ≥ 44×44 px。
- 焦点（Web 端）必须有清晰轮廓：2px `--accent-sage` + 4px offset。
- 表单错误必须通过 `aria-describedby` 关联。
- 图片上传 / 拍照的"权限拒绝"必须给出**可操作的下一步**（如引导到设置），不要用通用"权限被拒绝"。
- 时间展示：所有时间戳支持"2 分钟前 / 今天 14:23 / 2026-08-12"渐进精度。

## 9. 留给 K3 的视觉升级 hints

> 当你把这份 PRD 交给 K3 做视觉风格升级时，下面是**已确定的设计意图**：

1. **底色永远不纯白**：所有 surface 都用米白 (`#FFFCF4` 系) + 颗粒纸肌理。
2. **按钮主色 = 鼠尾草绿** `#7A9471`，永远不要再追加其他品牌色。
3. **卡片之间用色彩 + 1px 边线分层**，不要用阴影。
4. **图标手绘感**：线宽 1.5px、圆角端点、关键图标（购物袋、爱心、分类）可用 1 个点缀色的实心填充。
5. **数字字体**：`Inter` 或同系列；中文用 `LXGW WenKai` 优先。
6. **入场动效**主用 `ease-out-expo`；不要回弹弹性。
7. **庆祝**只 1 次迷你光晕，不要礼花 / 烟花。
8. **空状态插画**用线稿（≤ 80×80），不要大色块插画。
9. **布局**永远有节奏——分类页用 chip 流而不是网格墙，首页统计不要"大屏卡片"。
10. **文案永远第一/二人称**，不用 emoji 代替图标。
